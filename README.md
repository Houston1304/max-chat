# MAX chat — прототип веб-чата мессенджера MAX (React + GREEN-API)

Тестовое задание на должность «Фронтенд разработчик React»: интерфейс отправки и получения
**текстовых** сообщений в мессенджер **MAX** через сервис **GREEN-API**
(<https://green-api.com/max>), по внешнему виду <https://web.max.ru/>.

---

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
```

Продакшен-сборка:

```bash
npm run build    # папка dist/
npm run preview
```

### Подключение

1. Создайте инстанс MAX в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте его.
2. Скопируйте `idInstance` и `apiTokenInstance`.
3. Введите их на экране входа и нажмите **Подключиться**.
4. В поле «Новый чат» введите номер телефона получателя в международном формате
   (РФ `7XXXXXXXXXX` или РБ `375XXXXXXXXX`, 11–12 цифр) и нажмите **Создать**.
5. Напишите текстовое сообщение и отправьте его (кнопка или `Enter`).
6. Ответ собеседника появится в чате автоматически.

> Уведомления инстанса должны приходить через HTTP API: при входе приложение само вызывает
> `SetSettings` с пустым `webhookUrl` (согласно разделу «Технология HTTP API»).

| # | Требование | Реализация |
|---|------------|------------|
| 1 | UI для отправки/получения сообщений в MAX | Экраны входа, списка чатов и переписки: `src/components/*`, `src/App.jsx` |
| 2 | Сервис GREEN-API | Клиент API: `src/api/greenApi.js` (`https://api.green-api.com`) |
| 3 | Только текстовые сообщения | Обрабатываются только `textMessage` / `extendedTextMessage` (`handleNotification` в `src/App.jsx`) |
| 4 | Прототип — внешний вид web.max.ru | Палитра и раскладка сняты с web.max.ru: акцент `#007aff`, белые поверхности, линии `#e7e7e7`, макс. ширина 1280px, две панели «список чатов + переписка» (`src/styles.css`) |
| 5 | Максимально простой интерфейс, минимум функций | Вход, создание чата по номеру, отправка/получение текста, статусы инстанса. Без файлов, медиа, групп и прочего |
| 6 | Отправка методом `SendMessage` | `sendMessage()` → `POST /waInstance{idInstance}/sendMessage/{apiTokenInstance}` |
| 7 | Получение методом HTTP API | Цикл long-polling: `receiveNotification` (30 c) → обработка → `deleteNotification` (`useEffect` в `src/App.jsx`) |
| 8 | Технология React | React 18 + Vite, функциональные компоненты и хуки (`useState`, `useEffect`, `useMemo`, `useRef`) |

### Ожидаемый результат

| Шаг | Где реализован |
|-----|----------------|
| Ввод учётных данных `idInstance` / `apiTokenInstance` | `LoginScreen.jsx` → `getStateInstance` (проверка) + `setSettings` |
| Ввод номера получателя и создание чата | `Sidebar.jsx` → `checkAccount` (получение `chatId`) |

## Архитектура

```
src/
├── api/greenApi.js         # клиент GREEN-API (все вызовы API)
├── components/
│   ├── LoginScreen.jsx     # ввод idInstance / apiTokenInstance
│   ├── Sidebar.jsx         # список чатов, создание чата по номеру, статус инстанса
│   └── ChatView.jsx        # лента сообщений и поле ввода
├── App.jsx                 # состояние, отправка, цикл получения уведомлений
├── storage.js              # localStorage + форматирование телефона/времени
├── styles.css              # стили (палитра web.max.ru)
└── main.jsx                # точка входа React
```

**Используемые методы API**

| Метод | Вызов | Назначение |
|-------|-------|------------|
| `getStateInstance` | GET | валидация учётных данных, статус инстанса (каждые 15 с) |
| `setSettings` | POST | включение уведомлений HTTP API (`webhookUrl: ""`) |
| `checkAccount` | POST | номер телефона → `chatId` (создание чата) |
| `sendMessage` | POST | отправка текстового сообщения `{chatId, message}` → `{idMessage}` |
| `receiveNotification` | GET `?receiveTimeout=5` | long-polling входящих уведомлений |
| `deleteNotification` | DELETE | подтверждение обработки уведомления |

**Поток данных**

1. `sendMessage` → optimistic-сообщение со статусом «отправка» → после ответа API статус «отправлено».
2. Фоновый цикл опрашивает `receiveNotification`; каждое уведомление обрабатывается и удаляется через `deleteNotification` (FIFO-порядок гарантируется сервером).
3. `incomingMessageReceived` + `textMessage` → сообщение добавляется в чат соответствующего `senderData.chatId` (новый чат создаётся автоматически).
4. `outgoingMessageStatus` → обновляется статус доставки/прочтения, `stateInstanceChanged` → статус инстанса.
5. Чаты и сообщения сохраняются в `localStorage` и переживают перезагрузку страницы.

CORS: `api.green-api.com` отдаёт `Access-Control-Allow-Origin: *`, поэтому запросы выполняются
напрямую из браузера, прокси-сервер не требуется.

## Режим получения уведомлений

Постоянные вызовы `receiveNotification` — это штатная технология HTTP API из задания
(п.7): сервер держит соединение открытым (`receiveTimeout`) и отвечает сразу, как только
в очереди появляется уведомление, либо пустым ответом `HTTP 204` по таймауту.
Лимит `ReceiveNotification` — 100 запросов/сек на инстанс, режим приложения укладывается
в него с большим запасом.

Как экономится трафик (`src/App.jsx`):

| Приём | Эффект |
|-------|--------|
| `receiveTimeout = 30` c (разрешено 5–60) | один сетевой запрос примерно раз в 30 секунд вместо каждой 5-й секунды, отзывчивость не меняется — уведомление приходит сразу при появлении |
| минимальная пауза 1 с, если сервер ответил раньше (`204`) | защита от «холостого» цикла при мгновенных ответах |
| экспоненциальная задержка при ошибках: 5 → 10 → 20 → … → 60 c | вместо постоянных падающих запросов при недоступном API или неверных учётных данных; после восстановления статус инстанса обновляется автоматически |
| опрос приостанавливается, пока вкладка скрыта | уведомления не теряются — они хранятся в очереди GREEN-API 24 часа и приходят сразу при возврате во вкладку |
| остановка цикла при выходе (`logout`) и смене учётных данных | фоновых запросов после разлогина нет |
| `getStateInstance` — раз в 15 с (лимит 1/сек) | отображение статуса инстанса |

## Ограничения прототипа (сознательно, по п.5 «минимум функций»)

* только текстовые сообщения (нет файлов, статусов «печатает…», реакций);
* нет групповых чатов, поиска и истории из журналов (сообщения доступны с момента открытия приложения);
* учётные данные хранятся в `localStorage` браузера — прототип не предназначен для публичного развёртывания.
